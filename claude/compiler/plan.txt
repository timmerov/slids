compiler — PLAN (the main quest)

Feature implementation order. Items are open or LANDED; updated as we make
progress. Outstanding bugs / reach goals / deferred side-quests live in
todo.txt, not here. Detailed per-stage current-state notes (what each stage
does today, stage by stage) live in readme.txt.

Each phase adds primitives the next phase depends on. widen.cpp threads through
every conversion site as features land; treat each new expr/decl/assign site
as a widen call-out.

PIPELINE — current shape

    lex -> numeric -> grammar -> resolve -> constfold -> classify
        -> desugar -> optimize -> codegen

  resolve owns: parse::Entry vector population, frame push/pop, ident
  resolution (resolved_entry_id stamping), wrong-kind diagnostics
  (assign-to-function, call-a-variable), duplicate-decl + signature
  mismatch + arity-mismatch + multi-arg-print-intrinsic detection,
  type-spelling validation (widen::isKnownType for declared / return /
  parameter types), namespaces + enums (lowered to entries here), and the
  orphan-function check (declared-but-never-defined). Two passes per scope
  (collect decls then walk bodies) so forward references work.

  classify is type inference + (Phase 3) overload resolution. Stamps
  inferred_type / op_type, rejects no-common-type binaries, non-coercible
  operands for `! && || ^^` (and the `&&= ||= ^^=` aug-assigns), an if / while /
  for condition not coercible to bool, non-numeric
  shift sides, bitwise on float, and return correctness (non-void must end in a
  return — recursing into a trailing block and a both-arms-return if/else; void
  can't return a value). Reads entries via resolved_entry_id but never mutates
  the symbol table or pushes frames.

  * STRING LITERALS ARE `const char[N]` (LANDED 2026-07-21). A string literal is STORAGE,
    not a pointer: N bytes in the constant pool, N counting the terminating NUL. It used
    to be typed `char[]`, which made it a pointer that could never become storage — so
    `char a[6] = "hello"` was rejected ("Cannot assign 'char[]' to 'char[6]'") and would
    have needed an initializer rule of its own. Typed as the array it already is, that
    line is an ORDINARY same-type array init and several special cases retire instead of
    moving: sizeof's "content + null" stops being an exception to the type (it IS the
    type), and reaching a `char[]` parameter is the array->element-pointer DECAY slids
    already has — a non-mutable iterator param munges to `(const char)[]`, which the
    decayed literal matches at rung 2.
    CONST IS THE HONEST HALF: the pool is read-only. It buys nothing YET — argConvertCost
    deepStrips const on both sides, so a literal still binds to a `mutable char[]` param —
    but it makes the type true now so Phase-6 const enforcement has something real to
    enforce. THE SIZE IS FIXED, THE ELEMENT TYPE IS NOT: `char a[5]`/`char a[10]` are
    shape mismatches (the short form is the one C accepts, silently dropping the NUL),
    while `int a[6] = "hello"` is legal — char is uint8, so it rides the ordinary
    per-element widen.
    IT TAKES A POINTER TYPE FROM CONTEXT, exactly as nullptr does (classify's
    kStringLiteral arm). That is what makes the decay stick: the decay funnel replaces a
    node and RE-INFERS, and a string literal that stayed a string literal was re-stamped
    as the array again. Codegen keys on dest_type, not on the literal's own type — the
    pooled symbol IS the address (right wherever it decayed), and an array-value position
    loads the N bytes instead (storing the symbol was invalid IR).
    SURFACED A LATENT BUG: a tuple VALUE auto-promotes to a tuple-REFERENCE param, so the
    context at such a call is `(...)^` and kTupleExpr's per-slot context threading never
    fired. Harmless while no slot's type could depend on context; `macros.sl`'s `dump(#x)`
    broke the moment one could. Fixed by seeing through the pointer.
    Canon: assign/vardecl.sl (the initializer form + size negatives), lex/literal.sl (the
    type, and that N is the DECODED length — an escape is one byte), pointer/iterator.sl
    (the decay, to an iterator / a reference / a parameter), misc/sizeof.sl (the size).
  * POINTER COMPARISON CONVERTS (LANDED 2026-07-21). A comparison converts its
    operands like every other binary op. This arm alone used to demand IDENTICAL
    pointee types (nullptr the lone exemption), so `Base^ == Derived^`,
    `intptr == ptr`, and `T^ == T[]` were rejected — each a conversion the language
    already performs at a call, an assignment, and a return.
    THE COMMON TYPE comes from the SAME two predicates argConvertCost uses to rank a
    pointer ARGUMENT: ptrImplicitOk (nullptr->any, any->`void^`/`intptr`,
    iterator->reference of the same pointee) and ptrBaseUpcastOk (derived->base, the
    base at offset 0). Try lhs->rhs then rhs->lhs; the survivor is op_type, and reject
    only when NEITHER converts. ONE place decides what a pointer implicitly becomes,
    so a comparison and a call cannot drift apart on the answer.
    DIRECTION IS FORCED, not chosen: pointer->intptr is implicit while intptr->pointer
    needs an explicit cast, so a mixed pair settles on intptr; a derived/base pair
    settles on the base. Both operands convert to it, so `(p == q)` and `(q == p)`
    agree.
    NO CODEGEN WORK: emitBinary already emits both operands against op_type, and
    widen::convert already lowers ptr->intptr as a ptrtoint and ptr->ptr as a no-op.
    The bug was entirely classify refusing to name a common type.
    POINTERS ORDER SIGNED (same landing). codegen's comparison predicate no longer
    forces unsigned for a pointer op_type — pointers are signed in slids, and with a
    mixed pair settling on intptr an unsigned pointer ordering would make the same two
    addresses compare one way against each other and the other way against an intptr
    holding one of them. The only site that ORDERED pointers; the remaining unsigned
    icmps are synthesized i64 loop counters, and every other pointer icmp is eq/ne
    against null.
    UNCHANGED: a reference has no sequence position, so a pair involving one admits
    only `==` / `!=` — which also rejects ordering an iterator AGAINST a reference,
    since the pair settles on the reference. Iterators and intptr admit all six.
    NOTE the diagnostic still reads "Pointer comparison requires the same pointee
    type." — it never misfires (only genuinely incompatible pointees reach it), but it
    understates the rule, which is now compatibility rather than identity.
    Canon test/expression/compare.sl.)

    BINARY SIGNATURE RULE (2026-07-11, canon operator.sl 170-182) — a binary operator's
    FIRST parameter must be a REFERENCE TO THE ENCLOSING CLASS: `op+(Class^ a, ConstType b)`.
    It is the LEFT operand, and the op produces self from it. Enforced in
    validateOperatorSignatureTypes (n==2 — the only 2-param shape in the catalog; the swap
    rule is the template). CONSEQUENCE: a binary dispatches on the LHS OPERAND's class and
    NOTHING else — `tryLowerClassBinary` now takes only `lref`. An arbitrary `A:op+(B, C)`
    is rejected (the "worm-can": a class whose op+ takes two unrelated types could only ever
    be selected by the assignment TARGET's type).

    WHY IT MATTERS — OPERATOR PRECEDENCE. `+` binds tighter than `=`, so in `a = b + c` the
    binary must have a meaning fixed by its OWN operands BEFORE the `=` is consulted. Two
    mechanisms violated that and are DELETED (2026-07-11):
      - tryLowerClassBinary's CONTEXT arm — picked the result class from the expected type
        (the `=` target), which is what made a cross-class `Mat m = v1 + v2` expressible.
        Also its rhs-operand arm (a silent reversed-operand path).
      - tryLowerBinaryChain (+ flattenLeftChain, referencesEntry) — the target-keyed chain
        fuse. It ran BEFORE classify's infer loop precisely because it had no operand types
        yet, so it keyed on the TARGET; it re-associated `((m+n)+r)` into
        `a.op+(m,n); a.op+=(r)`, and it CLOBBERED `a` mid-expression (an operand evaluated
        later that reads `a` — e.g. `a = b + c + f()` — sees the half-built accumulator; the
        `referencesEntry` aliasing check could never catch an indirect read).
    Every class binary lowers bottom-up on its own operands. Aliasing (`a = a + b`) works for
    free — the accumulator reads the OLD `a`.

  * VIRTUAL METHODS + VIRTUAL DESTRUCTORS — LANDED. A virtual class (>=1 `virtual`
    member) carries a vtable pointer at OFFSET 0 (C++ ABI): a ROOT gets a hidden

  * REFINEMENTS (run-time-scope re-open) — LANDED 2026-07-28. Re-opening a class from a scope
    that ISN'T its own is an ILLUSION: it mints an anonymous zero-field DERIVED class ($T : T)
    that USURPS the base's name within that lexical scope, and instances declared outside are
    retargeted into it. Both the block form (`Class(){ ... }`) and the external form
    (`void Class:method(){ }`) trigger it, and BOTH go through ONE find-or-create funnel
    (mintUsurpers), so every opening in a scope merges into one usurper. Minting runs at the HEAD
    of relocateOutOfLineMembers — gated by a new runtime_scope flag, true only at the
    resolveStmtList / resolveFunctionBody call sites — so the external form finds its target as
    an ordinary local sibling and the relocation walk needed no special case. SOUND because a
    refinement adds NO fields, so $T is layout-identical to T → viewing a T instance as a $T is
    a free offset-0 no-op, and the whole thing rides the LANDED inheritance (_$base slot 0,
    base-chain member lookup: declaredMemberOverloads already stops at the most-derived frame
    carrying the name, so SHADOWING cost nothing).

    the usurpation, free), but the class SPELLS `$T`, because only a kSlid carries a def_id and
    sharing the name makes `$Data[5]` and `Data[5]` indistinguishable at the leaf — the retarget
    would silently no-op. The base is therefore PRE-RESOLVED onto the `_$base` param (its
    spelling would find the usurper itself); registerClassBody and pushBaseChain are guarded by
    is_usurper, and a relocated method's `_$recv` spelling uses the usurped name.
    THE RETARGET is Node::usurped_type, stamped by resolve (only it knows the scope) and read by
    classify (only it knows types) through one helper, stampUsurp, at the read and assign-target
    arms. It maps RECURSIVELY THROUGH THE TYPE CONSTRUCTORS (`T`, `T^`, `T[]`, `T[5]`, tuples) —
    without that it reaches only bare class lvalues and a container declared outside the scope
    never carries the refinement into a generic — and each scope's map is CHAIN-CLOSED so a
    nested refinement wins in one lookup.
    Delivers the scoping asymmetry for free (the original + sibling scopes can't name $T) and
    COMPOSES WITH TEMPLATES with no mechanism at all: the refinement is a real TYPE, so
    `bubblesort(array)` in the refining scope infers `T = $Data` and instantiates a second
    flavor whose body finds the refined method — retroactive, scoped conformance (slids's answer
    to a comparator / trait-impl, no orphan-rule problem). A PLAIN function is never
    re-instantiated, so a generic is the only thing that crosses the scope boundary.
    REJECTED (canon): a ctor/dtor and refining or adding a VIRTUAL method — checkUsurpers vets
    before registration (else the lifecycle-pairing rules report first and bury the reason) and
    marks the node, since relocation runs twice over a function body. Fields cannot be added:

    body still errors per-segment.

    statement of a function body).

    - DERIVING FROM AN OPAQUE CLASS (LANDED 2026-07-21). `Base : Derived` where Base is an
      imported incomplete class. The base sub-object KEEPS SLOT 0 — every upcast stays a no-op,
      which is the whole reason the base stays first — but its size is a runtime fact, so the
      derived class's OWN field offsets are not compile-time constants in an importer. They
      become LINK-TIME constants instead: the completer exports each slot k ≥ 1 as an ABSOLUTE
      symbol `@C__$off<k>` (2026-07-29; originally one folded `[N x i64]` table the importer
      loaded — slot 0, the base, is offset 0 by construction and gets no symbol).
      THE FLAG. widen::Type.runtime_layout, propagated in resolve (propagateRuntimeLayout, a
      fixpoint over the base chains run just before the by-value walk, so a chain
      `Opaque <- A <- B` marks both regardless of registration order). It keys ONLY on the
      base's persistent `...` header fact, so the completer and every importer compute it
      identically — the layout rule cannot disagree across the seam.
      IT IMPLIES OPAQUE, and that is the design. An opaque class already has a runtime size, a
      split `@C__$ctor`/`@C__$pctor` construction, and the importer-side layout rejections — the
      exact three things a derived class needs. So it JOINS that machinery (setSlidOpaque too)
      rather than growing a parallel copy; sizeof, ctor/dtor routing, and the runtime alloca all
      come free.
      OFFSETS (2026-07-29: ABSOLUTE symbols; originally a `[N x i64]` table the importer LOADED).
      The COMPLETER exports each slot k ≥ 1 as `@C__$off<k>`, an alias to the llc-folded
      `inttoptr(ptrtoint (getelementptr (<struct>, null, 0, k)))` off its real struct; an
      importer declares each and byte-GEPs by `ptrtoint (ptr @C__$off<k>)` — a link-time value
      relaxed to an immediate, no load. Slot 0 (the base) is offset 0 by construction and gets
      NO symbol (a 0-valued alias would be a `null` aliasee, which LLVM rejects); emitSlotAddr
      returns the base address unchanged, so an upcast still costs nothing. The completer's
      own layout and GEPs are UNTOUCHED — there the offsets are constants and it still indexes
      the struct directly.
      CODEGEN. llvmForRef lowers a runtime-layout class to the `{ i8 }` placeholder in a kDeclare
      TU, so nothing can structurally index it. Both the WRITE path (emitElementAddr's kSlid arm)
      and the READ path (emitExpr kIndexExpr) consult the offset symbols through ONE funnel
      (emitSlotAddr); the read side used to shortcut with a whole-object load + extractvalue,
      which has no whole object to load here — routing it back through the address funnel is what
      keeps a read and a write of one field on the same bytes. emitInitFill skips the SITE
      FIELD-FILL for any opaque class in an importer: `@C__$ctor` owns the whole default-fill.
      (That was a latent bug — invisible for a class with no visible fields, an empty `store
      undef`; fatal for one with them.)

      but not place them, and silently dropping the list is worse than refusing it); a `.sl`-LOCAL
      class over an opaque base (nothing outside the TU can name it, so no sibling exports its
      offsets); a VIRTUAL one (the base holds the slot the vptr needs). A bare global and
      `new T[n]` stay barred like the base's; by-value EMBEDDING of the derived class is legal
      since 2026-07-29 (a computed-layout leaf riding `@C__$size16` — canon TCase).

Phase 9 — templates
  * template functions                              LANDED (single-TU) 2026-07-21
    THE SHAPE: a template rides the existing machinery — it registers as an
    ordinary kFunction entry (is_template) in whatever frame declares it (file /
    namespace / block), so scoping, shadowing, and collisions are the normal
    ones, and its BODY stays in pristine parse state (every stage skips it)
    until a call binds the type-list. Resolve's scope state is transient, so
    registration SNAPSHOTS it at the body-resolution point; classify's
    on-demand instantiation re-installs the snapshot, binds each type parameter
    as a transparent kAlias to its bound type, and runs the CLONE through the
    normal per-function machinery (resolveFunctionBody + munge + constfold +
    classify) — so an instance IS an ordinary function to every later stage
    (spliced after its def node; desugar/codegen changes are just skips + the
    Itanium `I..E` type-args in symbolFor). INFERENCE finds T and nothing else:
    T binds exactly (a by-value T + array argument binds the decayed elem[];
    conflicts error), the not-template parts match by the NORMAL parameter
    rules (no constraint at inference; decay / rvalue-materialization aligners
    apply only to REACH a T — `dump(#answer)` infers through a tuple-ref). NO

CROSS-CUTTING — ONE-LEVEL OPERAND COERCION (v1 Phase-2, LANDED 2026-07-20;
                UNIVERSAL 2026-07-21)
  An argument that no candidate accepts directly, but that the parameter's class op= DOES (an
  int into op=(int64), a narrower int WIDENS in), is coerced ONE level: it is wrapped in a
  `(Class = arg)` class-conversion (reusing lowerClassConversion — default-construct a temp,
  run op=, yield it) and resolution is retried. The coerced value is a Class, so it never
  re-coerces — exactly one level; it then flows on as an ordinary rvalue operand (one
  countable temp, dead at the semicolon). No new node field, no desugar change. This is v1's
  Phase-2 (`String + "x=" + x`, string.slh) reached through v2's class-conversion path instead
  of v1's string-typed codegen match.
  IT IS A PARAMETER RULE, NOT AN OPERATOR RULE (2026-07-21). It landed reaching only the
  class-binary chain, as a lambda closed over stampClassBinary's candidate ids — so `a + i`
  coerced and `a += i` did not, the same operator disagreeing with itself over the spelling,
  and a plain `f(i)` for `f(Class^)` was rejected outright. The wrap is now ONE function
  (classify::coerceOperandToClass, beside findClassOperator; it rewrites the operand node IN
  PLACE so a caller holding only a Node& can use it) and every dispatch site retries with it:
    - pickOverload — the shared ranker funnel, so FUNCTIONS and METHODS both get it at once
      (coerceArgsForClassParams, keyed on classParamTarget: the one decode of "does this
      position want a class?", seeing through the `Class^` param munge).
    - the SINGLE-candidate paths in classifyCall / inferMethodCall, which never reach
      pickOverload: roll back checkArgAssign's rejection, coerce, ask again. inferMethodCall's
      copy also covers the operators REWRITTEN into method calls — comparison and op[] — so
      those need no arm of their own.
    - compound assign (`a += i`), which probes findClassOperator directly.
    - stampClassBinary, whose lambda is now a thin caller of the shared helper.
  A RETRY, NOT A RUNG. It deliberately is NOT a rung in argConvertCost: a rung would re-rank
  every call in the language and could silently move a call that resolves today onto a
  different overload. The retry runs only after ranking found NO viable candidate, so no
  program that compiles today can change meaning — the only calls it affects were errors.
  Canon operator.sl pins this: `pick("s")` still takes the direct `pick(char[])`.
  NOT WIRED to op<-- / op<--> (they share dispatchAssignInit, so the exclusion is deliberate):
  a move from a freshly built temp is pointless, and a SWAP with one silently discards the
  result — the compiler would be manufacturing a bug. Positions where candidates disagree
  about WHICH class are left uncoerced (picking one would be a guess); the ordinary "No
  matching overload" stands.
  Detail: readme-classes.txt chain-lowering + plan-evaluate.txt ADDENDUM 2026-07-20; canon
  operator.sl (classes Coerce / NoBuild / Ca / Cb) + evaluate.sl block CO (class Cvt, the
  temp count). This is what unblocked test/progress/string.sl (`str += x` for an int64), so
  string_test now compiles, links, and runs end to end.

CONVERSION SHORTHAND — CONVENTION OF CONVENIENCE #2 (landed 2026-08-03).
Canon: test/assign/typeconv.sl header. `lvalue type = expr;` desugars AT
PARSE to `lvalue = (type = expr);` — the long form's redundant `=` and
parens dropped; `x int = get_float();`, `int vol int = 3.14*r*r*h;`,
`obj.field Class = (1,2,3);`, chains `x float64 = intptr = ref;`.

    kStoreStmt / kVarDeclStmt-init of kConvertExpr the paren form builds —
    resolve, classify, desugar, codegen untouched. The whole cost is the
    statement recognizer: startsConvShorthand (a primitive keyword, an
    identifier-led target via looksLikeConvTarget, or a balanced `(...)`
    IMMEDIATELY followed by `=`), hooked at the name-led assign arm, the
    finishLvalueChain store tail, and the parseVarDeclStmt init slot.
  - THE DECL SHAPE WINS every collision (the canon's ambiguity clause):
    `x Amt = e` is `ident ident` — a decl with type x, even when x is an
    existing variable ("'x' is a variable, not a type"); `p^ Amt = e` /
    `arr[i] Amt = e` are suffix-run decl shapes. The long form is the escape
    hatch. ONE decl-gate carve-out: `v Vec<int> = e` — the second ident
    carries a type-arg group then `=`, a shape no decl can have (a declared
    name never carries type-args).
  - CLAIMED SPACE IS ERROR SPACE: every stolen shape failed to parse before
    ("Expected '='" / call-args type error), so no valid program changed
    meaning. The immediacy of the `(...)=` gate is what protects the VALID
    call chains `obj.m(a)^ = e` / `obj.m(a)[2] = e` — a suffixed paren lead
    stays a method call (so a suffixed tuple conv type needs the long form).

    temp feeds the outer op=(Amt^)).

THE `void;` REACHABILITY MARKER (landed 2026-08-03).
Canon: test/flow/void.sl header. `void;` is a no-op statement, legal
anywhere in a runtime code block (reachable ones included); its ONLY side
effect is marking unreachable code as intentional — the "Unreachable
statement." diagnostic is suppressed for the block that directly contains
one. No effect on any other diagnostic (unused / uninitialized still fire
inside dead code). The diagnostic now carries the suggestion note.
  - GRAMMAR: kVoid immediately followed by `;` -> kVoidStmt, an arm in the
    STATEMENT dispatcher only — so every non-runtime block (class body,
    switch clause list, import block, namespace, global group, template
    body) rejects the spelling naturally, each with its own existing error.
  - PER BLOCK: a top-level `void;` marks the block that directly contains
    it; a nested dead branch needs its own marker. An else-if chain gets
    ONE report and has no block of its own — a `void;` in ANY block along
    the chain suppresses it. All condition-form reports funnel through
    classify's reportUnreachableBranch (branchSuppressed / blockHasVoidStmt).
  - NEW DETECTION riding the same funnel: a const-false LONG-FOR flags its
    update block and body block independently (the update is author code;
    a short-for's synthesized update is never flagged); a constant SWITCH
    scrutinee flags every dead clause body — entry is the matching clause
    (else the default; neither = all dead), a trailing `continue` chains
    reachability into the next clause, analysis abandoned on any invalid
    label. A const-false do-while is NOT flagged (body runs once).
  - 2A (resolve): a `void;` in the same statement list suppresses the
    dead-tail report; the tail is then resolved like LIVE code (locals
    declared — unused sweep + DA apply unchanged), each tail statement
    marked Node.dead_code, and desugar's copyNode DROPS marked statements
    (nothing may be emitted after a terminator). Definitions are never
    marked — not executable, and a live call above the `return` may target
    one — so both classify's and codegen's endsInReturn now decide
    trailing-return correctness at the last EXECUTABLE statement (skipping
    `void;`, dead_code, defs). The canon's debugging idiom: `return; void;`
    ahead of temporarily-dead code that stays compiled and type-checked.
  - Coverage: void.sl positives (all four condition forms + chain + marker
    position anywhere + def-in-dead-tail + every for flavor as reachable
    no-op + do-while pin) and 16 negatives (diagnostic still fires per
    form, per-block isolation, unused/uninitialized unaffected, the six
    non-runtime-block rejections).
  Detail: readme.txt grammar statement dispatch, resolve 2A paragraph,
  classify constant-condition passage, codegen if-arm merge note.

ITERATOR STEPS JOIN THE ELEMENT-ADDRESS FUNNEL (landed 2026-08-04).
Found by guthrie: `Vector<Cluster>` op[]/end/next stepped ONE byte per
element while `reserve` allocated `sizeof(T)*n` correctly — the aggregated
bodies emit in the template source's TU, where Cluster (header-incomplete,
completed by the consumer) is OPAQUE, and every iterator step GEP'd the
element's LLVM type, i.e. the `{ i8 }` placeholder. THREE sites, one rule:
  - `iter ± int` (emitBinary), `iter[i]` (the emitElementAddr iterator arm),
    and the `++`/`--` bump (emitLeafBump) now step through emitElemAddr —
    the one element-address funnel — so a static element keeps its typed
    GEP (IR unchanged) and a runtime-sized one (opaque / computed layout)
    gets the byte GEP at the convention's size16 stride, the SAME stride
    the array-index path uses: `p + i` and `^arr[i]` land on the same
    bytes in every TU.
  - `iter - iter` divides by the matching stride via emitSizeValue (static:
    the LLVM type's size; dynamic: size16). The old divisor (elemBytes,
    deleted) was scalar-only and ASSERTED on any class element — so this
    also unbroke class-element iterator differences outright.
  - Coverage: test/import consumer.sl (opaque Rope, computed-layout Sack,
    complete-class Brick: ±, difference, `iter[i]` + bump identities, all
    against the array-index path) and tmpl_test.sl + tmpl_lib.slh/.sl
    tstep/tgap<Rope> (the arithmetic emitted in the TU where T has no
    layout — the guthrie shape).

TEMPLATE SPECIALIZATION + TYPE SETS (landed 2026-08-18).
Canon tmpl_special.sl: same-name same-arity template ARMS selected by the
deduced T's membership in a TYPE SET. `alias Name = <type-list>;` declares
a set (kTypeSet — a constraint, never a type): `|` adds, `|!` removes,
built LEFT TO RIGHT (removing an absent member is a no-op; `<!int8|Integers>`
therefore CONTAINS int8), a leading `!` complements over everything.
Members: concrete type spellings (incl. tuple types, typed pointers,
template instances), set names (kept as entry-id REFERENCES, evaluated
recursively), and category patterns — `^` reference, `[]` iterator,
`[N]`/`[N][M]` DEPTH-EXACT arrays, `()`/`(N)` unnamed tuples (no 1-tuples,
so a lone paren identifier is always arity). Concrete membership is
canonical per the binding canon: aliases shed, outer const peeled, buried
const kept.
  - Arms: `countof<T=Set>` (or a concrete type name — a one-type set IS
    full specialization), `<T=A[N]>`, `<T=[N][M]>`, `<T=(N)>`, and — added
    with the canon's inline-typeset lines — `<T=<int|float>>` /
    `<T=!<...>>`: an ANONYMOUS set with the full term grammar (named sets
    and patterns included; patterns are wildcards there — inline sets bind
    nothing), resolved at the snapshot point into the TemplateInfo, no
    entry minted; the `...>>` tail splits like a nested type-arg group's.
    Binders bind
    at instantiation off the matched T — element type as a transparent
    alias, dims/arity as pre-captured intptr CONST entries constfold
    substitutes like any named constant. `(A arg[N])` param spelling IS T
    (pattern = bare-T marker; the instance substitutes the bound type
    directly, sidestepping per-instance dim baking).
  - Selection at the CALL (classifyTemplateCall): deduce T, filter arms by
    arity then membership — zero = "No specialization", two+ = "Ambiguous
    specialization". No declaration-time disjointness pass, no catch-all:
    an unconstrained same-arity sibling still clashes; a different-arity
    one coexists (arity-only overloading unchanged). Plain-beats-template
    unchanged.
  - THE DECAY CHANGE (ruled with this landing): a bare-T param meeting an
    ARRAY argument binds the ARRAY TYPE (was: the decayed iterator).
    Arrays now ride the class/tuple convention rung — param munges to
    pointer-to-(const)-array (the existing array-param arm), the call
    passes the whole-array reference (rung 0), `mutable` opts writes in.

    string-literal call now spells `zork<char[]>`). This supersedes the
